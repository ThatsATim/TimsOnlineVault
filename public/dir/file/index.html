To be able to remote into any device at all it must also be properly configured on its network settings and have an available SVI. Please check [[SVI Example]] for more information. Making a remote connection to our network devices is simply a must when working in a real environment. Walking around plugging console cables in and out just doesn’t scale at all. Now lets see what it takes to configure secure remote access with encrypted SSH traffic. Lets start by making sure the device supports SSH!

  1. switch> enable
  2. switch# show ip ssh

If this command is not recognized the devices does not support SSH and telnet will have to be used as a last resort for remote access. Now lets go on to step 2 and configure the IP domain and a hostname.

  1. switch# configure terminal
  2. switch(config)# ip domain-name cisco.com
  3. switch(config)# hostname S1

Next we will generate the RSA key pairs which will be the base for our encryption.

  1. S1(config)# crypto key generate rsa This will prompt the question:
text 
How many bits in the modulus [512]:

A longer modulus is more secure but takes longer to process. Most examples I have come across use a modulus of 1024 bits. So go ahead and type it in and press enter!

text 
How many bits in the modulus [512]: 1024

Next up we need to create a user to login in with. Note that “secret” in this command is the password. 7. S1(config)# username admin secret cisco Now we can start accepting SSH traffic on our vty lines. Lets also make sure that we have to login locally on the device. 8. S1(config)# line vty 0 15 9. S1(config-line)# transport input ssh 10. S1(config-line)# login local Now to finish this configuration. By default SSH supports both version 1 and 2. Using version one these days is rather redundant so lets set our device to use version 2. 11. S1(config-line)# exit 12. S1(config)# ip ssh version 2 The last step is to make sure your pc is also configured with correct network configurations and that they can communicate with each other.

Please note that Saving configuration is always necessary to avoid loosing your work after a restart!
